GGG INVENTORY MANAGEMENT SYSTEM
WHAT IS ALREADY IN THE SYSTEM AND WHAT STILL NEEDS WORK

Prepared: October 5, 2026
Project: Laravel + React inventory management system
Local setup: Windows / Laragon / MySQL

PURPOSE
-------
This file is a quick checklist of the features that already exist and the
important work that remains. "Implemented" means the feature has code in the
project; it does not mean it is production-ready or deployed.


1. ALREADY IMPLEMENTED
----------------------

LOGIN AND PASSWORD RECOVERY
[x] Login with email and password using Laravel sessions.
[x] Check the current signed-in user and log out.
[x] Show/hide password controls.
[x] Password reset using a one-time email code (OTP).
[x] OTP is hashed in the database, expires after 10 minutes, has an attempt
    limit, and the reset endpoints are throttled.
[x] Create a staff account from the Staffs screen when signed in as the
    configured Super Admin. The server checks permission; the UI check alone
    is not the security rule.

PRODUCTS AND SUPPLIERS
[x] Product API supports listing, viewing, creating, editing and deleting.
[x] Supplier CRUD API exists.
[x] Products can reference suppliers.
[x] Product data is loaded from and saved to the database.
[x] Product list refreshes after saving changes.

STOCK CONTROL
[x] Load stock products and movement history from the backend.
[x] Record Stock In, Stock Out and physical stock-count Adjustments.
[x] Edit and delete stock movements.
[x] Save stock changes and movement history to the database.
[x] Prevent a stock operation from making the balance negative.
[x] Reconcile product balances and movement snapshots after edits/deletes.
[x] Regression tests cover key stock cases, including adjustments.

DASHBOARD AND SALES DATA
[x] Dashboard summary is loaded from a Laravel API.
[x] Dashboard uses available product, safety-stock, sales-history, movement,
    supplier and user data.
[x] Empty states are used when chart data is missing; dashboard does not need
    fake data to render.
[x] Sales-history API supports reading, adding and deleting sales observations.

OTHER
[x] Main application uses a Laravel Blade shell with React/Vite.
[x] Feature tests exist for login, password reset, dashboard, products and
    stock persistence.

4. KNOWN RISKS / CAUTIONS
-------------------------

- Do not expose the application publicly while inventory APIs are
  unauthenticated.
- Do not run database seeders against real data without checking their effects.
  InventorySeeder reads public JSON fixture files and deletes/rebuilds stock
  movement records.
- public/productSupplier.json, public/stockControl.json, and frontend sample
  constants are demo/seed data, not guaranteed current database contents.
- Previously observed local product quantities changed between checks. Verify
  the actual configured database before trusting any particular quantity.
- The local Gmail SMTP setup previously returned a credential rejection.
  Actual password-reset email delivery must be tested with valid configuration.
- Never copy .env passwords, SMTP app passwords, database credentials, or
  other secrets into this checklist, source control, or another AI chat.
- Do not treat movement variant_name as separate per-variant stock. Inventory
  balance is currently product-level.
